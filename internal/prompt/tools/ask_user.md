Asks the user one to four questions, each with two to four answers to choose from. The user picks one (or several, with multi_select) or types an answer of their own, so never add an "Other" answer yourself.

Use it when you need the user's decision to go on well: which of several reasonable approaches to take, a preference the request leaves open, or something only they know. Don't use it for what you can find out yourself by reading the code or running a command, and don't ask permission for what you were already asked to do: approvals have their own prompt.

- Make each question short and specific, ending in a question mark, and give it a header of at most 12 characters, such as "Database".
- Give each answer a label of a few words and, in description, what choosing it means or what it costs.
- Put the answer you recommend first and end its label with "(recommended)".
- In plan mode, use it to settle open questions before you present the plan.

The answers come back as text. Carry on with them; don't ask the same thing again.
